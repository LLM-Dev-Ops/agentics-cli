# ADR-055: Replace Mock Tests with Integration Tests Against Real Adapters

## Status: ACCEPTED

## Date: 2026-03-27

## Context

Production audit found: "12 of 13 test files test only mock adapters — they verify mocks return what they were told to return. Would pass 100% if all real adapters were deleted."

Current test pattern (generated by Phase 4 `tsContextTest()`):

```typescript
class MockSupplierAdapter implements ISupplierPort {
  private store = new Map<string, SupplierRecord>();
  async execute(command: string, payload: Record<string, unknown>) {
    const id = randomUUID();
    const record = { id, status: 'active', ... };
    this.store.set(id, record);
    return record;
  }
  // Tests verify THIS mock, not the real PostgreSQL adapter
}
```

This provides zero confidence that:
- SQL queries are syntactically correct
- Parameterized bindings work
- Filter logic produces correct WHERE clauses
- Schema matches runtime expectations

## Decision

### 1. Phase 4 must generate integration tests alongside mock tests

`tsContextTest()` must generate TWO test files per context:

**`tests/unit/{context}.test.ts`** — existing mock test (fast, CI-friendly)
**`tests/integration/{context}.integration.test.ts`** — tests real adapter against SQLite/pg-mem

### 2. Integration test pattern

```typescript
import { describe, it, expect, beforeAll, afterAll } from 'vitest';
import Database from 'better-sqlite3';  // or pg-mem for PostgreSQL compat

describe('SupplierAdapter (integration)', () => {
  let db: Database.Database;
  let adapter: SupplierAdapter;

  beforeAll(() => {
    db = new Database(':memory:');
    db.exec(`CREATE TABLE supplier_records (
      id TEXT PRIMARY KEY,
      status TEXT NOT NULL,
      created_at TEXT NOT NULL,
      updated_at TEXT NOT NULL,
      data TEXT NOT NULL
    )`);
    // Wire real adapter with real (in-memory) database
    const dbClient = {
      query: (sql: string, params: unknown[]) => db.prepare(sql).all(...params),
      execute: (sql: string, params: unknown[]) => db.prepare(sql).run(...params),
    };
    adapter = new SupplierAdapter(dbClient, new ConsoleTelemetry());
  });

  afterAll(() => db.close());

  it('execute() inserts a real record and getById() retrieves it', async () => {
    const result = await adapter.execute('CreateSupplier', { name: 'Test Corp' });
    expect(result.id).toBeDefined();

    const found = await adapter.getById(result.id);
    expect(found).not.toBeNull();
    expect(found!.data.name).toBe('Test Corp');
  });

  it('query() with filters produces correct WHERE clause', async () => {
    await adapter.execute('CreateSupplier', { region: 'EUROPE', name: 'EU Supplier' });
    await adapter.execute('CreateSupplier', { region: 'ASIA', name: 'Asia Supplier' });

    const result = await adapter.query({ region: 'EUROPE' }, 50, 0);
    expect(result.rows.every(r => r.data.region === 'EUROPE')).toBe(true);
  });

  it('query() with SQL injection attempt in filter key is blocked', async () => {
    const result = await adapter.query({ 'DROP TABLE--': 'x' }, 50, 0);
    // Regex filter /^[a-z_][a-z0-9_]*$/i blocks this key
    expect(result.rows).toBeDefined(); // Should not throw, just ignore bad key
  });
});
```

### 3. Add better-sqlite3 as optional dev dependency

Phase 4 `tsPackageJson()` must include:

```json
{
  "devDependencies": {
    "better-sqlite3": "^11.0.0",
    "@types/better-sqlite3": "^7.6.0"
  }
}
```

### 4. Runtime type validation on database results

Each adapter must validate query results against Zod schemas before casting:

```typescript
// Instead of: return rows as unknown as SupplierRecord[];
// Generate:
const validated = rows.map(row => {
  const parsed = SupplierRecordSchema.safeParse(row);
  if (!parsed.success) {
    console.error(JSON.stringify({ level: 'error', context: 'supplier', message: 'Schema validation failed on DB result', issues: parsed.error.issues }));
    return null;
  }
  return parsed.data;
}).filter(Boolean) as SupplierRecord[];
return validated;
```

## Consequences

- (+) Tests verify actual SQL execution, not mock behavior
- (+) Schema mismatches caught at test time, not production runtime
- (+) SQL injection prevention is tested with adversarial inputs
- (+) Runtime validation catches schema drift before silent data corruption
- (-) Integration tests are slower (~100ms vs ~1ms per test)
- (-) Adds better-sqlite3 dev dependency (~8MB)
- (-) Runtime validation adds ~0.5ms per query (negligible)

## Audit References

- "12/13 test files test only mock adapters" — integration tests added
