# ADR-PIPELINE-105: Deliverable Output Guarantee — Phase 7 ~80-Document Completeness & Acceptance Gate

**Status:** Proposed
**Date:** 2026-06-02
**Priority:** CRITICAL — Phase 7 (ADR-PIPELINE-098) *can* emit the 85-document pack, but nothing in the pipeline **guarantees** that the documents it emits are consulting-grade or even non-canned. The recurring failure mode (ADR-PIPELINE-100, ADR-PIPELINE-104) is that generation silently degrades to template skeletons and the run still reports `completed`. The user requirement is a *guarantee*: every full run must produce ~80 McKinsey/Accenture-grade deliverables, and a run that does not must say so — loudly — never report success on a pack of boilerplate.
**Builds on:** ADR-PIPELINE-098 (Phase 7 — the 85-document registry, 12 sectioned subdirs, 4 coherence invariants, `phase7-manifest.json`; this ADR adds the acceptance contract Phase 7 has always lacked), ADR-PIPELINE-104 (canned-fallback visibility — this ADR makes a canned fallback a *gate failure*, not just a visible banner), ADR-PIPELINE-100 (exemplar quality bar for ADRs — this ADR generalises the same "no canned output" standard to all deliverables and makes it enforceable), ADR-PIPELINE-094 (always-emit phase-result entries — this ADR refines the Phase 7 entry's status semantics), ADR-PIPELINE-066 (unit-economics as single financial source — the coherence checks read it).
**Companion:** ADR-PIPELINE-106 (Exemplar-Driven, LLM-Direct Deliverable Generation) defines *how* each document reaches the bar this ADR enforces. 105 is the gate; 106 is the generator that must pass it.

---

## Context

ADR-PIPELINE-098 established Phase 7 and the contract that "Phase 7 emits all 85 documents on every run." In practice it emits *files* — but their content quality is unenforced. Two gaps:

1. **No quality floor.** A deliverable that fell back to its canned template skeleton (e.g. an Investment Thesis full of `{{handlebars}}` residue, prompt echo, or generic phrasing like "leveraging synergies to drive transformational value") still lands as a `.md` file and still counts toward `deliverables_emitted`. The Phase 7 entry reports `completed`. The user opens the pack, finds boilerplate, and rejects the whole run — exactly the verdict recorded in ADR-PIPELINE-100: *"the same canned garbage I explicitly told you were unacceptable."*

2. **No completeness guarantee with teeth.** ADR-094 makes Phase 7 always push a `phases[]` entry, and the entry carries `deliverables_emitted: N`. But `completed` is reported whenever the writer loop finishes — not when N actually meets the target at acceptable quality. A run can emit 30 real docs and 50 skeletons and still be `completed`.

The registry (`src/pipeline/phase7/deliverables-registry.ts`) is 87 rows: ~76 genuinely-synthesized documents plus ~11 `mirrorsExisting` symlinks to earlier-phase artifacts. The synthesized set under `<runDir>/deliverables/` is therefore **~80 documents** — this is the "~80" of the requirement. This ADR defines what it means for that set to be *acceptably delivered* and makes the pipeline enforce it.

This ADR does not change *what* Phase 7 produces (registry unchanged) or *how* it dispatches (Ruflo, per ADR-091/098). It adds a single new stage — the **Deliverable Acceptance Gate** — that runs after generation and before Phase 7 reports its status.

---

## Decision

Eight rules. D1 fixes the target; D2–D4 define per-document acceptance; D5–D6 define run-level status and visibility; D7 wires in coherence; D8 covers rollout/kill-switch.

### D1. The guarantee target is the synthesized registry, not a magic number

The target `N_target` is **computed from the registry**, not hardcoded:

```
N_target = count(registry rows where mirrorsExisting is unset)   // the synthesized docs (~76)
N_total  = registry.length                                        // ~87 incl. mirrors
```

The acceptance gate evaluates the `N_target` synthesized documents. Mirrors are validated for *presence* only (the symlink resolves) — their quality is owned by the producing phase, not Phase 7. A test asserts `N_target` stays within `[72, 88]` so a careless registry edit that silently drops the pack to a handful of docs fails CI. "~80" in the requirement = `N_target` synthesized + mirrors present.

### D2. Every synthesized deliverable gets a verdict from a Deliverable Acceptance Checker

A new module `src/pipeline/phase7/acceptance-gate.ts` evaluates each synthesized deliverable and returns:

```ts
interface DeliverableVerdict {
  slug: string;
  section: number;
  present: boolean;            // file exists and is non-empty
  qualityScore: number;        // 0–100, see D3
  cannedFallback: boolean;     // generated by the template-skeleton path, not the LLM path (D5)
  coherenceOk: boolean;        // passes the coherence checks (D7)
  verdict: 'PASS' | 'WEAK' | 'FAIL';
  reasons: string[];           // human-readable; surfaced in manifest + index scorecard
}
```

Verdict mapping:
- `FAIL` — missing, empty, `cannedFallback === true`, or `qualityScore < 60`, or a hard coherence violation (financial figure not traceable to `unit-economics.json`).
- `WEAK` — present and non-canned but `60 ≤ qualityScore < 75`, or a soft coherence warning.
- `PASS` — `qualityScore ≥ 75`, not canned, coherence-clean.

### D3. Quality score is structural + anti-canned, measured against the exemplar

`qualityScore` is deterministic (no LLM in the gate — the gate must be cheap and reproducible). It is the weighted sum of three signals, each measurable from the rendered Markdown plus the deliverable's template-family exemplar (ADR-PIPELINE-106 D1):

| Signal | Weight | How measured |
|--------|--------|--------------|
| **Structural coverage** | 40 | Fraction of the exemplar's required structural elements present (headed sections, ≥1 data table where the exemplar has one, a recommendation/decision block, a sources footer). Mirrors the element-coverage idea from ADR-100. |
| **Anti-canned** | 40 | Penalties for: forbidden spin phrases (`src/synthesis/forbidden-spin-phrases.ts`), unresolved `{{placeholder}}` / `[TODO]` / `NOT_GENERATED` residue, prompt echo, and generic-boilerplate n-grams shared verbatim with the bare template. Score starts at 40 and is debited per hit. |
| **Run-data grounding** | 20 | Count of `<!-- fcv:... -->` provenance tags and concrete run figures (dollar amounts, dates, agent names) that resolve to real run artifacts vs. the template's defaults. Zero grounded figures → 0 here. |

Thresholds (`60`, `75`) live in `src/synthesis/phase-gate-thresholds.ts` alongside the existing gate thresholds, tunable without code change.

### D4. A canned fallback is a FAIL, not a degraded PASS

Per ADR-PIPELINE-104, a deliverable that fell back to its bare template skeleton already carries a visible marker. This ADR makes that marker **fail the gate**: `cannedFallback === true ⇒ verdict = FAIL`, regardless of structural score. Rationale: a clean-looking skeleton can score acceptably on structure while being exactly the "canned garbage" the user rejects. The only acceptable source for a synthesized deliverable is the LLM-direct path of ADR-PIPELINE-106. The skeleton remains as a last-resort *artifact so the file is never empty*, but it can never count as delivered.

### D5. Phase 7 status is derived from the pack-level pass rate

`auto-chain.ts` Phase 7 status (ADR-094 contract) is computed, not asserted:

```
passRate = count(verdict === 'PASS') / N_target

status = 'completed'              if passRate ≥ ACCEPT_RATE (default 0.90) and zero FAILs in §1 (executive)
       = 'partial'               if passRate ≥ DEGRADE_RATE (default 0.70)
       = 'failed'                if passRate <  DEGRADE_RATE
       = 'skipped-due-to-upstream' if Phase 1 artifacts absent (unchanged from ADR-098 D1)
```

Two non-negotiables:
- **Executive section is load-bearing.** Any `FAIL` in `01-executive/` (Executive Summary, Decision Memo, Board Deck, Recommendation Paper, Investment Thesis…) caps status at `partial` even if `passRate` is high. The board-facing docs are the product; a perfect appendix cannot compensate for a canned exec summary.
- **`completed` means the guarantee held.** When Phase 7 reports `completed`, ≥90% of ~80 documents are PASS-grade, non-canned, and coherent. That is the entire point of this ADR: `completed` becomes a claim the user can trust.

The Phase 7 entry gains: `deliverables_pass: P, deliverables_weak: W, deliverables_failed: F, pass_rate: R, acceptance: 'met' | 'degraded' | 'unmet'`.

### D6. Manifest + index carry a quality scorecard

- `<runDir>/deliverables/phase7-manifest.json` extends each per-doc record with the full `DeliverableVerdict` (D2).
- `<runDir>/deliverables/index.md` gains a **scorecard table** at the top: section · doc · verdict · score · reason-for-non-PASS. A reader sees the pack's health before reading a single deliverable. FAILs are listed first.
- The run's top-level summary prints one line: `Deliverables: P/N_target PASS, W weak, F failed — acceptance: <state>`.

### D7. Coherence checks are promoted from advisory to gating

ADR-098 D8 introduced a post-render coherence gate (financial figures vs `unit-economics.json`, single consensus banner, provenance tags, sources footer). This ADR consumes its output as the `coherenceOk` signal in D2:
- A financial figure with **no `fcv` tag** or a tag that does not resolve to `unit-economics.json` → hard violation → doc `FAIL`.
- A missing/contradictory consensus banner, or absent sources footer → soft warning → doc capped at `WEAK`.

The four ADR-098 invariants thereby become enforceable per-document, not just aspirational pack-level properties.

### D8. Rollout, kill-switch, and regression semantics

- Env switch `AGENTICS_DELIVERABLE_GATE={on,advisory,off}`, default **`advisory`** for one release (gate computes and reports verdicts + scorecard but does **not** change Phase 7 status), then flip default to **`on`**. `off` disables the gate entirely (skeleton-era behaviour).
- `advisory` exists so the gate's scoring can be calibrated against real runs before it can fail a pipeline — avoiding a thresholds-too-strict gate blocking every run on day one.
- Thresholds (`60`, `75`, `0.90`, `0.70`) are config in `phase-gate-thresholds.ts`; changing them is not a code change and is logged in the manifest so a run's acceptance is reproducible against the thresholds in force.

## Consequences

### Positive
- `completed` on Phase 7 becomes a *guarantee* of ~80 consulting-grade, coherent, non-canned documents — the exact requirement.
- Canned fallback can no longer masquerade as a delivered document (closes the ADR-100/104 defect at the contract level).
- The scorecard turns "is this pack any good?" from a manual read of 80 files into one table.
- Calibration via `advisory` mode de-risks turning the gate on.

### Negative / Risks
- A genuinely good run can be marked `partial` if the deterministic score is miscalibrated (false negative). Mitigation: `advisory` warm-up period + tunable thresholds.
- Deterministic anti-canned heuristics can be gamed by an LLM that avoids forbidden phrases while still being shallow. Mitigation: ADR-106's exemplar bar attacks the root cause; the gate is the backstop, not the only quality mechanism.
- Adds a post-generation pass (cheap — pure text analysis, no LLM) to every run.

### Neutral
- Registry and template set are unchanged. This is purely an acceptance layer.

---

## Alternatives Considered

1. **LLM-judge the gate.** Score each doc with a Claude "is this McKinsey-grade?" call. Rejected as the *gate*: non-deterministic, expensive at ~80 docs, and unreproducible for CI. The deterministic gate is the contract; LLM judgment belongs in generation (ADR-106), not in the pass/fail decision.
2. **Hardcode N = 80.** Rejected: the registry is the source of truth (ADR-098 D3); hardcoding drifts from it. D1 derives the target and range-checks it instead.
3. **Keep canned fallback as a degraded PASS.** Rejected: this is precisely the behaviour the user has repeatedly classified as unacceptable.
4. **Make the gate fail the whole pipeline immediately.** Rejected: Phase 7 must still emit every file (so the user can inspect what went wrong); the gate sets *status*, it does not abort writing.
