# ADR-PIPELINE-018: Simulation Lineage Threading to ADRs

**Status:** Accepted
**Date:** 2026-04-08
**Supersedes:** None

## Context

The pipeline's lineage gate (ADR-004) enforces that ERP commands carry a `simulation_id` for traceability. However, ADRs generated by the Phase 2 pipeline had no link back to the simulation that spawned them. When a simulation produced ADRs → DDD → implementation prompts, there was no way to trace an ADR back to simulation `sim-446c85e6` that originated the architectural decisions.

This breaks the simulation → execution lineage chain at the ADR level. A future engineer reading ADR-089 ("Logistics Optimizer bounded context") could not determine which simulation produced it, what agents were consulted, or what consensus level was achieved.

## Decision

1. Add an optional `simulationId` field to the `Phase2ADRRecord` type.

2. In the ADR generator's `generateADRs()` function, extract the `execution_id` (or `run_id`) from Phase 1 artifacts and stamp it on every generated ADR.

3. Update `renderADRMarkdown()` to include a `## Lineage` section when `simulationId` is present.

4. Log the simulation linkage at generation time: `[adr-generator] Linking ADRs to simulation: <id>`.

## Alternatives Considered

- **Store lineage only in manifest.json** (rejected): The manifest links files to simulations, but individual ADRs don't carry their lineage. Reading an ADR in isolation provides no traceability.
- **Separate lineage database** (rejected): The ruvector lineage store handles artifact-level lineage, but ADR-level lineage should be embedded in the ADR itself for self-contained readability.

## Consequences

- [+] Every ADR is self-contained with its originating simulation ID
- [+] ADR markdown files include a `## Lineage` section linking to the simulation
- [+] Downstream prompt generation can thread simulation ID through to implementation prompts
- [-] ADRs generated without a simulation context (e.g., manual invocation) have no lineage section
- [~] `simulationId` is optional — no breaking change to existing consumers

## Files Changed

- `src/pipeline/phase2/types.ts` — Added `simulationId?: string` to `Phase2ADRRecord`
- `src/pipeline/phase2/phases/adr-generator.ts` — Extract and stamp simulation ID, render lineage section
