# ADR-PIPELINE-068: ESM-Safe Simulation Lineage Helper in Scaffold

**Status:** Accepted
**Date:** 2026-04-11
**Priority:** HIGH — Silent lineage break in every generated project
**Originating Review:** OPERA Sustainability Prototype Readiness Review (2026-04-11), Simulation Alignment 7/10

## Context

The OPERA review surfaced a subtle but corrosive defect:

> "Fix `loadSimulationId()` — ESM `require()` is silently failing; use `readFileSync` on `.agentics/plans/manifest.json`. Restores full simulation → execution lineage and removes `sim-unknown` from executive output."

The generated prototype's `src/config.ts` contained a `loadSimulationId()` helper that used CommonJS `require()` to read the manifest. Because the generated project runs under `"type": "module"` (a scaffold default), the `require` call throws and is swallowed by a `try/catch`, producing a silent fallback to the string `sim-unknown`. Every downstream artifact then carries `sim-unknown` instead of the real run id — meaning the prototype's audit log, OPERA posts, and executive summary are all disconnected from the pipeline simulation manifest.

Root cause is in the pipeline scaffold, not the coding agent: the implementation prompt (ADR-PIPELINE-039 style) tells the coder to "load the simulation id from `.agentics/plans/manifest.json`" without providing an ESM-safe snippet to paste in. Different agents produce different incorrect implementations, all broken the same way.

## Decision

### 1. Ship a Correct `simulation-lineage.ts` in the Scaffold

`src/pipeline/auto-chain.ts` already emits `logger.ts`, `config.ts`, `errors.ts`, and `middleware.ts` into `.agentics/plans/scaffold/src/`. Add a fifth file `simulation-lineage.ts` with an ESM-safe reader:

```typescript
// Auto-generated by Agentics pipeline (ADR-PIPELINE-068)
// Loads the simulation lineage from the pipeline manifest. ESM-safe.
import { readFileSync, existsSync } from 'node:fs';
import { resolve, dirname } from 'node:path';
import { fileURLToPath } from 'node:url';

export interface SimulationLineage {
  readonly simulationId: string;
  readonly traceId: string;
  readonly runId: string;
  readonly source: 'manifest' | 'env' | 'fallback';
}

const MANIFEST_CANDIDATES = [
  '.agentics/plans/manifest.json',
  '.agentics/runs/latest/manifest.json',
];

function findManifest(startDir: string): string | null {
  let dir = startDir;
  for (let i = 0; i < 6; i++) {
    for (const rel of MANIFEST_CANDIDATES) {
      const candidate = resolve(dir, rel);
      if (existsSync(candidate)) return candidate;
    }
    const parent = dirname(dir);
    if (parent === dir) break;
    dir = parent;
  }
  return null;
}

export function loadSimulationLineage(): SimulationLineage {
  // 1. Environment override (CI, tests, container runs)
  const envSim = process.env['AGENTICS_SIMULATION_ID'];
  const envTrace = process.env['AGENTICS_TRACE_ID'];
  if (envSim) {
    return { simulationId: envSim, traceId: envTrace ?? envSim, runId: envSim, source: 'env' };
  }

  // 2. Manifest from the project tree (ESM-safe — no require())
  try {
    const here = dirname(fileURLToPath(import.meta.url));
    const manifestPath = findManifest(here);
    if (manifestPath) {
      const raw = JSON.parse(readFileSync(manifestPath, 'utf-8')) as Record<string, unknown>;
      const runId = String(raw['run_id'] ?? raw['runId'] ?? '');
      const simulationId = String(raw['simulation_id'] ?? raw['simulationId'] ?? runId);
      const traceId = String(raw['trace_id'] ?? raw['traceId'] ?? simulationId);
      if (simulationId) {
        return { simulationId, traceId, runId, source: 'manifest' };
      }
    }
  } catch {
    // fall through to fallback
  }

  // 3. Explicit fallback — caller decides whether to fail
  return { simulationId: 'sim-unknown', traceId: 'trace-unknown', runId: 'run-unknown', source: 'fallback' };
}

export function requireSimulationLineage(): SimulationLineage {
  const lineage = loadSimulationLineage();
  if (lineage.source === 'fallback') {
    throw new Error(
      'ECLI-LIN-068: simulation lineage unavailable — set AGENTICS_SIMULATION_ID or place manifest.json under .agentics/plans/',
    );
  }
  return lineage;
}
```

### 2. Implementation Prompts Must Reference the Scaffold File

`src/pipeline/phase2/phases/prompt-generator.ts` currently instructs the coder to "copy `src/middleware.ts` from scaffold." Add an equivalent instruction for `simulation-lineage.ts`:

> "For simulation lineage, copy `src/simulation-lineage.ts` from scaffold and call `loadSimulationLineage()` (permissive) or `requireSimulationLineage()` (strict). **Do NOT use `require()`** — the generated project is ESM. Never invent a `loadSimulationId` helper; use the scaffolded one."

### 3. Ban `require(` in Generated Code via Post-Generation Validator

Add a rule to the post-generation validator from ADR-PIPELINE-065:

| ID | Rule | File Pattern | Check |
|---|---|---|---|
| PGV-011 | No `require(` calls in generated TypeScript | `src/**/*.ts` (excl. tests, scripts) | Match `(^|\s|=)require\s*\(` — error severity |

This catches not only this defect but any future ESM/CJS mixup.

### 4. Fallback Visibility

When `loadSimulationLineage()` returns `source: 'fallback'`, the scaffold's demo template must prepend a loud banner to demo output:

```
⚠️  Simulation lineage unavailable (source: fallback)
    All audit entries and ERP posts will carry sim-unknown.
    Fix: place .agentics/plans/manifest.json in the project tree
    or set AGENTICS_SIMULATION_ID.
```

Makes the break visible at demo time instead of landing in an executive summary.

## Implementation

1. Add `simulation-lineage.ts` emitter to `src/pipeline/auto-chain.ts` alongside the existing scaffold writes (~lines 236–320).
2. Update implementation prompt template in `src/pipeline/phase2/phases/prompt-generator.ts` to mention the scaffold file and the `require(` ban.
3. Add PGV-011 to the post-generation validator rule set (ADR-PIPELINE-065).
4. Update demo template in the same `auto-chain.ts` emitter to print the fallback banner when appropriate.
5. Unit tests in `tests/pipeline/scaffold/simulation-lineage.test.ts`:
   - env override works
   - manifest reader walks up 6 dirs and finds `.agentics/plans/manifest.json`
   - `requireSimulationLineage()` throws when source is fallback
   - No `require(` anywhere in the emitted source

## Acceptance Criteria

1. Every generated project contains `src/simulation-lineage.ts` with `loadSimulationLineage` and `requireSimulationLineage` exports.
2. Running a fresh pipeline on any query and then executing the generated `npx tsx src/demo.ts` prints a real `sim-...` id, not `sim-unknown`.
3. PGV-011 fires against any regenerated project that uses `require(`.
4. `AGENTICS_SIMULATION_ID=sim-test-42 npx tsx src/demo.ts` prints `sim-test-42`.
5. Removing the manifest and running the demo prints the fallback banner — not a silent default.

## Consequences

### Positive
- Fixes a class of defect (ESM/CJS mismatch) uniformly across all generated projects
- Restores simulation → execution lineage without relying on the coding agent to get it right
- Makes fallback conditions loud, not silent

### Negative
- Scaffold surface grows by one file — acceptable; the file is <100 lines
- Coding agents that prefer to write their own lineage helper must be explicitly told not to; prompt drift risk mitigated by PGV-011
