# ADR-PIPELINE-078: Deep Canonical JSON for Audit Hash Chain

**Status:** Accepted
**Date:** 2026-04-12
**Priority:** MEDIUM — Silent audit-chain integrity gap
**Originating Review:** Ramco Aviation Catering Readiness Review (2026-04-12), Code Quality 7/10
**Builds on:** ADR-PIPELINE-048 (Governance Hash-Chained Audit), ADR-PIPELINE-075 (Scaffolded Persistence)

## Context

The Ramco review noted a subtle but real bug in the generated audit service:

> "Secondary: `AuditService.canonical()` only sorts top-level keys, so payload-hash determinism is fragile for nested objects."

Every generated prototype builds its own `AuditService` from the same implementation prompt. The current prompt tells the coding agent to canonicalize the payload before hashing so the chain is deterministic — but "canonicalize" gets implemented as:

```typescript
private canonical(obj: Record<string, unknown>): string {
  const sorted: Record<string, unknown> = {};
  for (const k of Object.keys(obj).sort()) sorted[k] = obj[k];
  return JSON.stringify(sorted);
}
```

This sorts **top-level keys only**. A payload like `{ decision: { risk: { score: 8, owner: 'alice' } } }` has two equivalent representations depending on insertion order in `decision.risk`, and the generated canonicalizer hashes them to different values. Tamper detection then fires spuriously on benign re-serializations, or misses real tampering inside nested objects.

The hash chain is still useful as a defense-in-depth control, but its promise — "mutating any field in any past entry breaks verify()" — is false for nested mutations. A reviewer who knows this can forge an entry by rearranging nested keys until the hash happens to match.

**The fix is to ship a recursive canonical JSON helper as a scaffold primitive** and have every generated audit log use it. Canonical JSON is a well-understood problem (RFC 8785 JCS) but a minimal implementation is ~30 lines. Every audit service should use the same helper, not re-invent it.

## Decision

### 1. Scaffold `src/persistence/canonical-json.ts`

Add a new scaffold file with a recursive canonicalizer:

```typescript
// Auto-generated by Agentics pipeline (ADR-PIPELINE-078)
// Deterministic JSON serialization for audit hash chains and idempotency
// keys. Follows JCS (RFC 8785) closely enough for our needs: object keys
// are sorted lexicographically at every depth; arrays preserve order;
// strings, numbers, booleans, and null use their standard JSON encoding.
//
// This implementation is intentionally minimal. It does NOT handle:
//   - undefined (rejected — pass null instead)
//   - BigInt (rejected — convert to string at the boundary)
//   - circular references (throws)
//   - Date objects (serialize as ISO string at the boundary)

export type CanonicalJsonValue =
  | string
  | number
  | boolean
  | null
  | readonly CanonicalJsonValue[]
  | { readonly [key: string]: CanonicalJsonValue };

export class CanonicalJsonError extends Error {
  constructor(message: string) {
    super(`ECLI-CJ-078: ${message}`);
    this.name = 'CanonicalJsonError';
  }
}

const VISITED = new WeakSet<object>();

/**
 * Canonicalize `value` into a deterministic JSON string. Keys are sorted
 * at every level; arrays preserve order; primitives use standard encoding.
 */
export function canonicalJson(value: unknown): string {
  VISITED.clear?.(); // tolerate old engines that lack WeakSet.clear
  try {
    return serialize(value);
  } finally {
    // WeakSet holds nothing after serialize unwinds; nothing to do
  }
}

function serialize(value: unknown): string {
  if (value === undefined) {
    throw new CanonicalJsonError('undefined is not canonicalizable — pass null instead');
  }
  if (value === null) return 'null';
  if (typeof value === 'boolean') return value ? 'true' : 'false';
  if (typeof value === 'number') {
    if (!Number.isFinite(value)) {
      throw new CanonicalJsonError(`non-finite number: ${String(value)}`);
    }
    // Use JSON's native number stringification (IEEE-754 shortest round-trip).
    return JSON.stringify(value);
  }
  if (typeof value === 'string') {
    return JSON.stringify(value);
  }
  if (typeof value === 'bigint') {
    throw new CanonicalJsonError('BigInt is not canonicalizable — convert to string at the boundary');
  }
  if (Array.isArray(value)) {
    if (VISITED.has(value)) throw new CanonicalJsonError('circular reference in array');
    VISITED.add(value);
    const parts = value.map(item => serialize(item));
    VISITED.delete(value);
    return '[' + parts.join(',') + ']';
  }
  if (typeof value === 'object') {
    if (VISITED.has(value as object)) throw new CanonicalJsonError('circular reference in object');
    VISITED.add(value as object);
    const record = value as Record<string, unknown>;
    const keys = Object.keys(record).sort();
    const pairs: string[] = [];
    for (const key of keys) {
      const v = record[key];
      if (v === undefined) continue; // JSON-compatible: skip undefined fields
      pairs.push(JSON.stringify(key) + ':' + serialize(v));
    }
    VISITED.delete(value as object);
    return '{' + pairs.join(',') + '}';
  }
  throw new CanonicalJsonError(`unsupported value type: ${typeof value}`);
}

/**
 * Hash a value with SHA-256 using its canonical JSON representation.
 * Callers get a stable hex digest independent of key insertion order.
 */
export function canonicalSha256Hex(
  value: unknown,
  crypto: { createHash: (a: string) => { update: (s: string) => { digest: (f: string) => string } } },
): string {
  return crypto.createHash('sha256').update(canonicalJson(value)).digest('hex');
}
```

The helper is **pure** and has no runtime dependencies beyond what the caller passes in (`crypto` is injected so the helper works in tests without hitting `node:crypto`).

### 2. Scaffold `src/persistence/audit-hash.ts`

A second scaffold file that wraps `canonicalSha256Hex` with audit-log-specific conventions:

```typescript
// Auto-generated by Agentics pipeline (ADR-PIPELINE-078)
// Audit hash-chain helper. Use this instead of hand-rolling
// `createHash('sha256').update(JSON.stringify(...))`.
import { createHash } from 'node:crypto';
import { canonicalJson } from './canonical-json.js';

export interface HashChainInput {
  readonly prevHash: string;
  readonly entryId: string;
  readonly actor: string;
  readonly action: string;
  readonly entityType: string;
  readonly entityId: string;
  readonly payload: unknown;
  readonly createdAt: string;
}

/**
 * Deterministically hash an audit entry's content + its link to the
 * previous entry. Payload keys are sorted at every depth so mutations
 * at any nesting level change the hash.
 */
export function hashAuditEntry(input: HashChainInput): string {
  const body = canonicalJson({
    prevHash: input.prevHash,
    entryId: input.entryId,
    actor: input.actor,
    action: input.action,
    entityType: input.entityType,
    entityId: input.entityId,
    payload: input.payload,
    createdAt: input.createdAt,
  });
  return createHash('sha256').update(body).digest('hex');
}
```

The helper is ~30 lines. Every generated `AuditService.append()` method is expected to call `hashAuditEntry(...)` — not roll its own.

### 4. PGV-022 — Audit Services Must Use `hashAuditEntry`

Add to the post-generation validator:

| ID | Rule | File Pattern | Check |
|---|---|---|---|
| PGV-022 | Audit services must hash entries with `hashAuditEntry` from the scaffold | `src/**/audit*.ts`, `src/**/services/audit*.ts`, `src/**/services/audit/**` (excl. tests) | Match `createHash\s*\(\s*['"]sha256['"]\s*\)\.update\s*\(\s*JSON\.stringify` — flag as error; also match any function named `canonical` declared in the file as warning |

The rule catches two common regressions:
1. Hand-rolled `JSON.stringify(obj)` before hashing (the exact Ramco bug)
2. Re-implementing a `canonical()` helper locally instead of importing from the scaffold

Suggested fix output: `"Import { hashAuditEntry } from '../persistence/audit-hash.js' and call it with the entry fields."`

>     const hash = hashAuditEntry({ ...full, payload: entry.payload });

>     return stored;
>   }
> }

> DO NOT write your own `canonical()` helper.
> DO NOT call `JSON.stringify(payload)` before hashing — it is not canonical
> and nested mutations will escape tamper detection.

### 6. Verify Uses the Same Helper

The audit service's `verify()` method recomputes each entry's hash with the same `hashAuditEntry` call used at append time, then walks the chain checking `prevHash` linkage. A tamper in any nested field changes the canonical representation and therefore the computed hash — verification fails immediately.

### 7. ADR-075 Repository Integration

The `AppendOnlyAuditRepository` from ADR-075 stores the already-hashed entry. The repository does NOT recompute the hash — that's the service's job. This separation keeps the repository concerned with storage and the service concerned with semantics.

## Acceptance Criteria

1. Every generated project contains `src/persistence/canonical-json.ts` and `src/persistence/audit-hash.ts`.
2. `canonicalJson` produces identical output for `{b:1,a:2}` and `{a:2,b:1}` at any depth.
3. Audit services in newly generated projects import `hashAuditEntry` rather than rolling their own canonical helper.
4. Mutating `entries[0].payload.nested.score` in a generated project breaks `verify()`.
5. PGV-022 fires against a synthetic file calling `createHash('sha256').update(JSON.stringify(entry))`.
6. Regenerating the Ramco catering prototype with ADR-078 active produces an audit service whose tamper-detection covers nested payload fields.

## Consequences

### Positive

- Audit hash chains deliver what they promise: tamper-detection at every depth, not just at the root.
- The canonical JSON helper is reusable — other pipeline features (idempotency keys, request fingerprints) can consume it without reimplementing.
- PGV-022 catches a class of defect that currently requires manual review to find.
- The scaffold's canonical implementation is the only one that needs maintenance; regressions in one project can't happen.

### Negative

- Canonical serialization is slightly slower than `JSON.stringify` — ~2x on a realistic payload. Audit paths are not hot, so the cost is noise.
- The helper rejects `undefined`, `BigInt`, and circular references. Coders used to `JSON.stringify` swallowing these silently will hit friction. The scaffold comment documents the boundary conversions.
- RFC 8785 JCS has subtle edge cases around numeric encoding (shortest round-trip). Our implementation uses `JSON.stringify` for numbers which is a close-but-not-identical match. For audit hashing this is fine; if we ever need to interop with other JCS implementations, a more careful number encoder can replace the number branch.
